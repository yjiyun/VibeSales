# Human Handoff Skill

## 目标

在需要人工介入的场合，让主 Agent 停止自行给出结论，转为产出一份人工可直接接手的交接说明。

## 触发时机

是否需要转人工由下层 `HumanHandoffTriggerRule`（ruleCode `human-handoff-trigger`）判定，结论经
`RuntimeContext` 写入系统提示词。**本 Skill 不重新判断是否该转人工**，只消费已给出的结论并决定措辞。

规则当前识别以下情形（按顺序，命中即转）：

- `explicit_human_request`：客户明确要求人工
- `severe_allergy`：出现严重过敏反应
- `sensitive_medical_context`：涉及医疗敏感判断
- `emotional_or_out_of_scope`：情绪激烈或超出可答范围

## 当前输出目标

- 明确告知客户正在转接人工，不要承诺具体处理结果或时限
- 产出可交接摘要：客户诉求、已收集到的关键信息、尚缺的信息
- 涉及过敏或医疗敏感时，不给诊断、不给用药建议

## 约束

- 不在 Skill 中固化转人工的硬阈值，判定以下层规则为准
- 不臆造工单号、人工姓名或排队位置
- 需要人工的场合不得继续给业务结论，避免与人工口径冲突

## 交接摘要结构

如当前链路需要生成给内部同事看的交接单，优先按以下字段组织：

```json
{
  "user_name": "客户在企微上的称呼",
  "intent": "意图枚举里的一个",
  "reason": "为什么必须真人接手，一句话说清判据",
  "user_input": "客户触发转人工的原话",
  "ai_responses": "本轮之前已经对客户说过的话",
  "unresolved_issue": "客户当前仍未被解决的核心问题"
}
```

## 写作要求

- `reason` 写判据，不只写结论，如“面部大面积红肿并持续加重”
- `unresolved_issue` 只保留一件最关键的未解决事项
- `user_input` 尽量保留原话，不转述、不美化
- `ai_responses` 要让人工一眼看出哪些话题已经问过
- 对客措辞与内部交接说明分离，不把内部工单内容直接发给客户
