# Recovery Handling Skill

## 目标

用于正式项目第一版中的恢复判断链路，帮助主 Agent 在收到用户消息后，优先判断这条消息是在继续上一轮未完成任务，还是开启一个新的处理轮次。

## 当前阶段

当前处于 `P1` 最小闭环阶段，本 Skill 主要承担“流程意图说明”作用，具体硬规则仍以下层代码实现为准。

## 触发时机

每轮对话开始前，编排层会先预取历史摘要、任务板、客户画像，并由 `RecoveryDetectionRule` 计算
“当前是否在续接上一轮未完成话题”。这些结构化结果会写入 `RuntimeContext`，再由
`Middleware.onSystemPrompt(...)` 追加到系统提示词。**这份 Skill 不需要、也不应该自己重新判断
是否续接**，只需要消费系统提示词里已经给出的结论，在措辞和语气上体现对应处理方式：

- 若结论是"续接"，参考下方"当前输出目标"续接客户之前的话题
- 若结论是"新话题"，按新一轮正常处理，不要主动假设存在未完成的历史话题

## 依赖信息

- 当前采用“编排层预取 + 系统提示词注入”模式，不直接调用 Tool
- 历史摘要来源：`getHistorySummary`
- 任务板快照来源：`getIntentQueue`
- 客户画像摘要来源：`getCustomerProfile`
- 恢复结论来源：`RecoveryDetectionRule`

## 当前输出目标

- 判断是否按恢复态处理
- 给出恢复处理提示
- 返回目标意图占位结果

## 约束

- 不在 Skill 中直接固化关键硬规则
- 关键硬规则以下层代码或 Tool 为准
- 本 Skill 当前只用于最小闭环中的流程编排表达
