# After Sales Skill

## 目标

让主 Agent 面对售后诉求时先判清类型再回应，避免把该受理的诉求挽留成争执，也避免把可解释的问题直接升级。

## 触发时机

编排层已预取会话历史摘要（`getHistorySummary`）、任务板（`getIntentQueue`）与客户画像
（`getCustomerProfile`），结论写入 `RuntimeContext` 并追加进系统提示词。本 Skill 在主意图落到售后时消费。

## 依赖信息

- 历史摘要（判断是否已沟通过同一问题）：`getHistorySummary`
- 未完成任务：`getIntentQueue`
- 客户画像与购买记录：`getCustomerProfile`
- 订单与售后状态查询：`crm_query`（经 MCP `business-tools` 提供）

## 当前输出目标

- 先归类诉求：退换货、物流签收、质保、使用后不适
- 属于应直接受理的情形（如质量问题、明确要求退换）时直接推进，不做挽留
- 属于可先行解释的情形（如用法误解）时先解释，并说明客户仍可选择退换
- 收口时把处理结论与待办写回任务板，便于下轮或人工续接

## 约束

- 不编造退换政策、时限、运费承担方与赔付标准，以租户规则为准
- 客户情绪激烈或反复不满时让位于 `human-handoff`，不强行挽留
- 使用后不适涉及过敏或医疗敏感时不给诊断与用药建议
- 不在 Skill 中固化售后政策，硬规则以下层代码或租户配置为准
