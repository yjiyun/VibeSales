# 推荐咨询

对应原工作流 U6 段（`138324 U6-05` → `1453797 U6-06` → `109304 U6-09` / `140503 U6-11` → `173346 U6-18`），
是执行率第二高的业务分支（82.7%）。

## 何时使用

- 意图码为 `product_recommend`
- 客户在问「适合我吗」「有没有推荐」「发个链接」「搭一套」

## 四段内部流程

1. **推进判断**：当前是继续收集画像，还是已经可以推荐。
2. **槽位提取**：从这一轮话里抽 `skinType` / `concerns` / `budget` / `targetEffect` / `preferredCategory`。
3. **追问或决策**：信息不够 → 只追问一个字段；够了 → 给方案。
4. **回复生成**：把决策写成人话。

## 硬规则不在这里判

`canRecommend`、充分度打分、追问轮次上限由 `ProfileCompletenessRule` /
`FollowUpRoundLimitRule` 计算，结论通过阶段上下文给你。**不要自己重算，也不要覆盖结论。**

你只消费这几个结论：

- 是否具备最小推荐条件
- 本轮是否还允许追问
- 本轮最多给几条候选

## 追问纪律

- 一次只问一个字段，候选字段只有三个：`budget`、`skinType`、`concerns`。
- 已经问过同一个字段又没得到答案时，不要再追同一个字段，换一个或直接给方案。
- 追问要给客户一个好回答的问法，不要列表式盘问。

## 给方案时

- 最多两条，能一条讲清就一条。
- 每条都要说清「为什么适合你现在这个情况」，不要只报产品名。
- 只推谷雨自家产品。
- 价格、库存、活动、成分浓度、见效时间一律先通过 `retrieveKnowledgeBase` 核实；查不到就说去确认。

## 不要做

- 不要一次抛五六个产品让客户自己挑
- 不要把护肤品说成能治皮肤病
- 不要跳过肤质与诉求直接推爆款
